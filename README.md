# Birthday Voting Game

משחק יום הולדת אינטרנטי עם:
- מסך מארח
- כניסה מהנייד דרך QR או קישור
- סרטון לכל סבב
- פתיחת הצבעה אחרי הסרטון
- תוצאות חיות
- שמירה של סשנים, הצבעות וסרטונים על השרת

## איך מכניסים סרטונים

יש 2 דרכים:

1. העלאה מתוך המסך
פשוט לוחצים על `העלה סרטון לסבב` במסך המארח.
הקובץ נשלח לשרת ונשמר בתיקיית האחסון.

2. קבצים קבועים מתוך `public/videos`
שמים קובץ בתיקייה `public/videos`, ואז מזינים בשדה הווידאו נתיב כמו:

```text
/videos/round-1.mp4
```

## פיתוח מקומי

התקנה:

```bash
npm install
```

פיתוח Frontend בלבד:

```bash
npm run dev
```

הרצת השרת שמגיש גם את ה־API וגם את ה־build:

```bash
npm run build
npm run start
```

ברירת המחדל המקומית:
- אפליקציה: `http://localhost:4173`

## אחסון

השרת שומר מידע בתיקיית האחסון:
- סשנים והצבעות: `sessions.json`
- סרטונים שהועלו: `uploads/`

ברירת מחדל מקומית:

```text
storage/
```

אפשר לשנות בעזרת משתנה סביבה:

```text
STORAGE_DIR
```

## פריסה קבועה ב-Railway

הפרויקט מוכן ל־Railway דרך `Dockerfile` ו־`railway.json`.

### מה חשוב ב-Railway

צריך ליצור:
1. Service אחד מה־repo הזה
2. Volume קבוע שממופה ל־`/data`

### משתני סביבה מומלצים

אין חובה להגדיר `PORT`, Railway מגדיר אותו לבד.

כדאי להגדיר:

```text
STORAGE_DIR=/data
```

### תהליך העלאה

1. מעלים את הפרויקט ל־GitHub
2. ב־Railway בוחרים `New Project`
3. בוחרים `Deploy from GitHub repo`
4. מחברים את הריפו הזה
5. Railway יזהה את `Dockerfile`
6. מוסיפים Volume וממפים אותו ל־`/data`
7. מגדירים Environment Variable:

```text
STORAGE_DIR=/data
```

8. עושים Deploy

### בדיקת תקינות

אחרי העלייה, הכתובת הזאת צריכה לעבוד:

```text
/health
```

## מבנה חשוב בפרויקט

- `src/App.tsx` - ממשק המארח והניידים
- `src/App.css` - עיצוב האפליקציה
- `server.mjs` - שרת האפליקציה וה־API
- `public/videos/` - סרטונים קבועים מראש
- `storage/` - נתונים וסרטונים מקומיים

## למה זה הפתרון הנכון לאירוע

כי הוא לא תלוי במחשב שלך:
- האתר רץ על שרת קבוע
- הסרטונים נשמרים על volume קבוע
- ההצבעות נשמרות על השרת
- המשתתפים יכולים להיכנס מכל מכשיר

## דשבורד חירום — אימות ומשתמשים (בשרת)

כשהאתר מוגש מ-`server.mjs`, הכניסה וההרשאות נאכפות בשרת (`em-auth.mjs`): סיסמאות מוצפנות ב-scrypt, סשן ב-cookie מסוג HttpOnly, נעילה אחרי 5 ניסיונות כושלים, וניתוק אחרי 30 דקות חוסר פעילות.

- **הפעלה ראשונה:** נוצר משתמש `admin` עם סיסמה חד-פעמית שמודפסת ללוג השרת (ב-Railway: Deploy Logs). אפשר לקבוע אותה מראש ב-`EM_ADMIN_PASSWORD`. בכניסה הראשונה חובה להחליף סיסמה.
- **שכחת סיסמה:** מריצים `node server.mjs --reset-admin` (עם `STORAGE_DIR` זהה) ומקבלים סיסמה חד-פעמית חדשה.
- **נתוני המשתמשים והיומן:** `STORAGE_DIR/em_users.json` ו-`em_audit.jsonl` (חשוב שהתיקייה תהיה על Volume קבוע).
- **מקלטים:** הנתונים משותפים בין כל המכשירים המחוברים (סנכרון כל 5 שניות). סיסמאות Wi-Fi וטלפונים של דיירים נשלחים רק למי שיש לו הרשאת עריכה במקלטים.
- שאר הלשוניות (אירועים, מפונים, קוביות מצב) עדיין נשמרות בדפדפן בלבד.
- פתיחה כקובץ מקומי (`file://`) משתמשת במצב המקומי הישן ללא אכיפה אמיתית.

## הפעלה מכל מחשב

**אפשרות א׳ — שרת קבוע באינטרנט (מומלץ לחירום, זמין מכל מקום):** פריסה ב-Railway לפי הסעיף "פריסה קבועה ב-Railway" למעלה. בנוסף להגדרות שם:
1. ב-Variables: `STORAGE_DIR=/data` ו-`EM_ADMIN_PASSWORD=<סיסמה התחלתית>` (נדרשת החלפה בכניסה הראשונה).
2. Volume ממופה ל-`/data` — שם נשמרים כל הנתונים, המשתמשים והיומן.
3. הכתובת: `https://<הדומיין שלך>/emergency`

**אפשרות ב׳ — מחשב אחד ברשת מקומית (בלי אינטרנט):** בתיקיית הפרויקט מפעילים `start-server.bat` (נדרש רק Node.js). הוא מציג כתובות כמו `http://192.168.x.x:8080/emergency` שאפשר לפתוח מכל מחשב או טלפון באותה רשת, ומדפיס סיסמת admin חד-פעמית. הנתונים נשמרים בתיקייה `storage`. יש להשאיר את החלון פתוח, ולאשר ל-Windows גישה ברשת בפעם הראשונה.

### נתונים משותפים
כל המחשבים המחוברים רואים אותם נתונים ומתעדכנים זה מזה תוך כ-5 שניות: אירועים, קוביות מצב, מפונים, מקלטים (+דיירים ופעילות), תשתיות, מרכזי משפחות והערכת מצב. מה שלא משותף: נקודות סימון ידניות על המפה.

### ייבוא ועדכון מ-Excel
- **מקלטים** ו-**מפונים**: כפתורים "📤 ייצוא Excel", "📄 תבנית ריקה" ו-"📥 ייבוא Excel" בכל לשונית.
- הזרימה לעדכון: מייצאים → עורכים באקסל → מייבאים. שורה עם "מזהה מערכת" מעדכנת את אותה רשומה; בלי מזהה — לפי שם (מקלט) או ת"ז / שם+כתובת (תושב). תא ריק = ללא שינוי; ייבוא לא מוחק רשומות.
- לפני החלה מוצגת תצוגה מקדימה (כמה חדשים / יתעדכנו / אזהרות).
- גיליון "דיירים" (במקלטים) ו"בני בית" (בתושבים) מחליפים את הרשימה של אותו מקלט / תושב.
